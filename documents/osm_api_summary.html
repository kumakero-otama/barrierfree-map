OpenStreetMap / Valhalla / フィッティング関連API

このプロジェクトにある
地図まわりのAPIまとめ

調べた結果、このプロジェクトには OpenStreetMap 関連APIだけでなく、 Valhalla を使ったマップマッチングや経路フィッティングのAPIもあります。 このページでは、それらを中学生にも分かるようにまとめます。

今回見つかったAPI一覧

  • GET /api/osm-tactile-ways: OpenStreetMapから点字ブロック関連データを探す
  • GET /api/match: 1つのGPS点を近くの道にぴたっと合わせる
  • POST /api/trace: たくさんのGPS点をまとめて道に合わせ、通った経路らしく整える
  • GET /api/count: マップマッチングAPIが今月どれだけ使われたかを見る

OpenStreetMapって何?

OpenStreetMap は、みんなで作る地図データです。 道、歩道、建物、信号、点字ブロックのような情報まで、世界中の人が少しずつ登録しています。

このプロジェクトでは、その OpenStreetMap の情報を読み取るAPIと、 GPSのずれを地図に合わせて直すAPIの両方を使っています。

GET /api/osm-tactile-ways

これは、地図のある場所の近くにある「点字ブロック関係のOpenStreetMapデータ」を取り出すAPIです。 サーバーは OpenStreetMap を直接全部読むのではなく、Overpass API という検索サービスに問い合わせて、 その結果をアプリで使いやすい形に直して返します。

何を入力するのか

centerLat 必須。中心にしたい場所の緯度です。
centerLng 必須。中心にしたい場所の経度です。
radiusKm 省略可。どこまで広く探すかを km で指定します。指定しないと 10km で、最大でも 10km までです。

つまり、「どの場所を中心に」「どれくらいの広さで探すか」を渡します。

どんなデータを探すのか

このAPIは、OpenStreetMapの中でも主に点字ブロックに関係するタグを探します。

tactile_paving

点字ブロックがあるか、両側にあるか、見やすい色か、など。

tactile_paving:orientation

ブロックの向き。進行方向に対して平行か垂直か。

tactile_paving:direction

道の左側か右側か。

tactile_paving:condition

状態がよいか、普通か、など。

tactile_paving:pattern

棒状の誘導ブロックか、点状の警告ブロックか。

どんな出力をするのか

success うまく成功したかどうか。
centerLat, centerLng 中心として使った場所。
radiusKm 実際に使われた検索半径。
count 見つかった地物の数。
features 見つかった地物の一覧。地図に線や点として描きやすい形で入っています。

features の中身

1つ1つの地物は、主に次の2種類です。

  • LineString: 線です。歩道や道沿いの点字ブロックのように、長さのあるものを表します。
  • Point: 点です。特定の1か所だけを表します。

各地物には、たとえば次のような情報が入ります。

  • osm_way_id または osm_node_id: OpenStreetMap上の番号
  • osm_type: way か node
  • matched_tag_key: どのタグで見つかったか
  • matched_tag_value: そのタグの値
  • geometry: 地図に置くための位置情報

裏側で使っている外部API

このAPIの裏では、OpenStreetMap系の検索サービス Overpass API の POST /api/interpreter を使っています。

相手先 既定では overpass-api.de
パス /api/interpreter
メソッド POST
送る形式 application/x-www-form-urlencoded で data=... を送る
中身 Overpass QL という検索用の文を送る

これは /api/osm-tactile-ways を受け取ったサーバーが、サーバー → Overpass API と送る検索文の例です。

[out:json][timeout:25];
(
  way(around:1000,35.6812,139.7671)["tactile_paving"~"^(yes|both|contrasted)$"];
  node(around:1000,35.6812,139.7671)["tactile_paving:pattern"~"^(bars|dots)$"];
);
out geom;

意味は、「この場所の近く 1000m にある、点字ブロック関係のタグを持った way や node を JSON で返して」です。

具体例

GET /api/osm-tactile-ways?centerLat=35.6812&centerLng=139.7671&radiusKm=1 は、フロントエンド → このプロジェクトのAPI に送るリクエスト例です。

意味は「東京駅の近く1kmで、点字ブロック関係のOpenStreetMapデータを探して」です。

次のJSONは、そのあと このプロジェクトのAPI → フロントエンド に返るレスポンス例です。

{
  "success": true,
  "centerLat": 35.6812,
  "centerLng": 139.7671,
  "radiusKm": 1,
  "count": 2,
  "features": [
    {
      "type": "Feature",
      "properties": {
        "osm_way_id": 123456,
        "osm_type": "way",
        "matched_tag_key": "tactile_paving",
        "matched_tag_value": "yes"
      },
      "geometry": {
        "type": "LineString",
        "coordinates": [[139.76, 35.68], [139.77, 35.68]]
      }
    }
  ]
}

エラーの例: 400 invalid_center は緯度や経度がおかしいとき、 502 osm_upstream_error は外部の地図検索サービスで失敗したときです。

Valhalla とフィッティングって何?

スマホのGPSは、ほんとうは歩道の上にいるのに、少しずれて車道や建物の上に見えることがあります。 そこで使うのが Valhalla です。 これは地図データを使って、「たぶん本当はこの道の上だろう」と位置を直してくれる仕組みです。

この「ずれたGPSを道に合わせること」を、このページでは フィッティング や マップマッチング と考えてください。

GET /api/match

これは 1点だけ を直すAPIです。 今いる場所のGPS 1つを送ると、近くの歩道や道に合わせた位置を返します。

何を入力するのか

lat 必須。今の緯度です。
lng 必須。今の経度です。
prevLat, prevLng 任意。1つ前の位置です。今の実装では必須ではありません。
sessionId / sessionUuid 任意。どの記録セッションの点かを表します。
userId 任意。ユーザーIDです。セッション保存に使われます。
deviceUuid 任意。どの端末から来たかを見分けるために使われます。
seq 任意。何番目の点かを表します。
record=1 任意。元のGPS点と直した後の点を保存して、あとで精度確認しやすくします。

どんな出力をするのか

lat 道に合わせて直したあとの緯度。
lng 道に合わせて直したあとの経度。
count 今月このAPIが何回使われたか。
month その回数がどの月のものか。たとえば 2026-07 のような形です。

簡単にいうと、「GPSの1点を送ると、道の上っぽい1点が返る」APIです。

裏側で使っている外部API

このAPIの裏では、Valhalla の POST /locate を使っています。 これは「この点の近くにある道を調べて、いちばん近そうな場所を返して」というAPIです。

相手先 既定では localhost:8002。環境変数 VALHALLA_HOST と VALHALLA_PORT で変更可能
パス /locate
メソッド POST
送る形式 application/json

次のJSONは、このプロジェクトのAPI (/api/match) → Valhalla (/locate) に送っているリクエスト例です。

{
  "verbose": true,
  "locations": [
    { "lat": 35.6812, "lon": 139.7671, "radius": 10 }
  ],
  "costing": "pedestrian",
  "costing_options": {
    "pedestrian": {
      "walkway_factor": 0.1,
      "sidewalk_factor": 0.1
    }
  }
}

ここで pedestrian は「歩く人向け」、 radius: 10 は「10mくらいの近くで探して」、 walkway_factor と sidewalk_factor は「歩道をかなり優先して」という意味です。

GET /api/match?lat=35.6812&lng=139.7671 は、フロントエンド → このプロジェクトのAPI に送るリクエスト例です。

このあと返ってくるのは、このプロジェクトのAPI → フロントエンド のレスポンスで、本文では lat, lng, count, month が返ると説明しています。

エラーや特別な返し方: 400 invalid_coordinates は座標がおかしいとき、 429 rate_limited は短時間に送りすぎたとき、 204 は上限到達や上流応答の処理失敗などで、中身なしで返るときです。

POST /api/trace

これは たくさんのGPS点をまとめて 直すAPIです。 歩いた点の列を送ると、「本当はこの道を通ったはず」という形に整えて返します。

何を入力するのか

shape 必須。GPS点の配列です。各点は lat と lon を持ちます。
userId 任意。誰の記録かを表します。
sessionId 任意。セッションにひもづけて、あとで経路保存にも使えます。
source 任意。デフォルトは valhalla です。
costing 任意。OpenAPIにはありますが、実装では歩行者向けの pedestrian が使われます。
shape_match 任意。デフォルトは map_snap です。GPS列を道に合わせるモードです。
filters 任意。Valhallaから受け取る情報をしぼる設定です。

次のJSONは、フロントエンド → このプロジェクトのAPI (/api/trace) に送るリクエスト例です。

{
  "sessionId": "abc-123",
  "shape": [
    { "lat": 35.6812, "lon": 139.7671 },
    { "lat": 35.6813, "lon": 139.7674 },
    { "lat": 35.6815, "lon": 139.7679 }
  ]
}

どんな出力をするのか

返り値は「Valhallaの結果そのまま」に近い JSON です。 そのため項目は多いですが、大事なものだけ言うと次の通りです。

  • edges: どの道の区間を通ったと考えたか
  • matched_points: 入力したGPS点が、どこに合わせられたか
  • shape: 道に合わせて整えられた線の情報

さらに sessionId があれば、サーバー側で「このセッションの通った経路」として保存されます。

裏側で使っている外部API

このAPIの裏では、Valhalla の POST /trace_attributes を使っています。 これは「点の列を見て、どの道を通ったかを推定して」というAPIです。

相手先 既定では localhost:8002。VALHALLA_HOST と VALHALLA_PORT で変更可能
パス /trace_attributes
メソッド POST
送る形式 application/json

次のJSONは、このプロジェクトのAPI (/api/trace) → Valhalla (/trace_attributes) に送っているリクエスト例です。

{
  "shape": [
    { "lat": 35.6812, "lon": 139.7671 },
    { "lat": 35.6813, "lon": 139.7674 },
    { "lat": 35.6815, "lon": 139.7679 }
  ],
  "costing": "pedestrian",
  "shape_match": "map_snap",
  "trace_options": {
    "search_radius": 10
  },
  "costing_options": {
    "pedestrian": {
      "walkway_factor": 0.1,
      "sidewalk_factor": 0.1
    }
  }
}

つまり、「歩く人として考えて、10mくらいの近くから歩道を優先しつつ、 この点の列がどの道だったかを推定して」と頼んでいます。

Valhalla から返ってきたJSONは、そのままに近い形で このプロジェクトのAPI → フロントエンド へ返されます。

エラー: 400 invalid_json は送ったJSONの形がこわれているときです。 Valhallaへの通信や結果の解釈に失敗すると 500 系になります。

GET /api/count

これは地図そのものを返すAPIではありませんが、 /api/match などのマップマッチングが今月どれだけ使われたかを見るためのAPIです。

入力

特に必要ありません。

出力

count 今月使われた回数。
max 今月の上限回数。
month 対象の月。
allMonths 月ごとの回数一覧。

まとめ

このプロジェクトでは、OpenStreetMapの情報を読むAPIと、ValhallaでGPSを道に合わせるAPIが組み合わさっています。 /api/osm-tactile-ways は Overpass API の /api/interpreter を使い、 /api/match は Valhalla の /locate、 /api/trace は Valhalla の /trace_attributes を使っています。
