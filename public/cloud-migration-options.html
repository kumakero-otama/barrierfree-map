StepBy クラウド移行案比較

前提：第一ステップでValhallaを廃止し、ブラウザフィッティング・OSM変更案・認証・監査を完成させた後に移行する。2026-08-05時点の公式無料枠を確認。

現時点の第一候補： まずはVPSへそのまま移す案が、コード変更と障害点が最少。無料運用を優先する実験案は「Cloud Run＋Neon＋GitHub Pages＋オブジェクトストレージ」。利用が増えたらDBだけ有料化しやすい。
案構成例無料枠の可能性現在のNode/PostgreSQLとの相性主な変更注意点評価
1. VPSへ丸ごと移行Ubuntu VPS
Node/PM2＋PostgreSQL＋画像		Google Compute Engineの対象米国リージョンでe2-micro 1台、標準ディスク30GB等のFree Tier。ただし性能・転送量は小さい。最良OS、TLS、バックアップ、監視を移設。アプリ変更は最小。保守・セキュリティ更新は自分で実施。1GB級RAMでは余裕が少ない。移行しやすさ1位
1-B. Oracle無料VPSOCI Ampere A1 VM
Node/PM2＋PostgreSQL＋画像		Always Freeで合計2 OCPU・12GB RAM相当、Block Volume 200GBなど。現行一体構成を載せやすい。最良ARM64互換を確認してサーバーを丸ごと移設。リージョンによって空き容量不足があり、アイドルVMが回収される場合がある。無料枠にSLAなし。無料VPS第一候補
2. Google中心GitHub PagesまたはFirebase Hosting
Cloud Run
Neon/Supabase PostgreSQL
Cloud Storage		Cloud Runは月200万リクエスト、180,000 vCPU秒、360,000 GiB秒が無料枠。Cloud Storage無料枠は対象米国リージョン等の条件あり。良いNodeをコンテナ化。ローカルファイル保存をCloud Storageへ変更。DB接続プール調整。Cloud SQLには恒久的な小規模無料枠を期待しにくいため、無料優先なら外部Postgres併用。無料実験の第一候補
3. AWS中心GitHub Pages/S3
Lambda＋API Gateway
RDS PostgreSQLまたは外部Postgres
S3		Lambdaは月100万リクエスト・400,000 GB秒の無料枠。DBやAPI Gatewayは契約時期・期間限定枠に注意。中HTTPサーバーをLambda向けへ分割。画像をS3へ。コールドスタートとDB接続対策。サービス数と権限設定が多く、個人開発では運用が複雑。完全無料を維持しにくい。拡張性重視
4. Cloudflare中心Pages
Workers
Neon PostgreSQL＋Hyperdrive、またはD1
R2		Workersは10万リクエスト/日、R2は10GB/月、Hyperdriveは10万DBクエリ/日。静的アセットは無料。中〜低Node APIをWorkersランタイム向けへ変更。ファイルをR2へ。Postgres継続ならHyperdrive。Freeは1回10ms CPU制限。画像処理・大きい依存関係・従来Node APIは書換え量が多い。D1へ移すならSQL移行も必要。軽量API向け
5. Supabase一体型GitHub Pages
Supabase Postgres/Auth/Storage/Edge Functions		無料でDB 500MB、Storage 1GB、Edge Functions 50万回など。1週間非アクティブで停止。DBは良いPostgreSQL移行は容易。画像Storageと一部APIをEdge Functionsへ移す。既存Google認証との整理。無料DBは小さく、非アクティブ停止・バックアップ制約あり。Node APIを全部そのままは動かせない。管理画面重視
6. Render簡易PaaSRender Web Service
Render Postgres
Object Storageは別		無料Web Serviceあり。ただし無料Postgresは1GBで30日後に失効するため、本番DBには不適。良いNodeをほぼそのままデプロイ可能。無料DBが30日限定でバックアップなし。本番は有料DBまたはNeon等が必要。短期検証向け

推奨A：安全優先

小規模VPS 1台へNode、PostgreSQL、画像を移す。現行構造を維持でき、第一ステップ完了後の移行事故が最も少ない。

無料VPSは性能・リージョン・在庫に左右されるため、本番では月額上限を決めた低価格VPSも比較対象にする。

推奨B：無料枠優先

GitHub Pages＋Cloud Run＋Neon＋Cloud Storage。現在のNode/PostgreSQLを比較的維持しながら、アクセスが少ない時間はAPIを停止できる。

現在の画像は本番で約142MBなので、無料ストレージ容量内から開始できる可能性が高い。

採用前に測るもの

  • 月間APIリクエスト数
  • Cloud Run換算のCPU時間
  • DB容量と月間増加量
  • 画像容量と転送量
  • 同時接続数
  • バックアップ保持日数
