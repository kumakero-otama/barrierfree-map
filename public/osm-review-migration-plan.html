OSM公開審査・ゲスト除外・既存データ移行

新規記録を即時送信する方式から、管理者が1件ずつ確認して承認した記録だけをOSMへ送る方式へ変更するための実行順です。本番OSMへの試験送信は、この計画の実装・自動試験には含めません。

決定済み

  1. 航空写真は国土地理院のシームレス空中写真を使用し、OSM・GPS・変更予定経路を別レイヤーで重ねる。
  2. 審査待ち1件ごとに kumakero.otama@gmail.com へ通知する。
  3. 管理者画面はGoogle認証を使い、kumakero.otama@gmail.com だけを許可する。
  4. 旧ローカル本番DBの328記録を対象とし、経路あり276件を一次候補、経路なし52件を要調査に分ける。
  5. 却下記録は削除せず理由を保存し、再審査可能にする。旧データでゲストと判別できるものはOSM対象外とする。

1. 保存方式と審査キュー

  • ✅ 新規記録の保存処理からOSM即時送信を外し、StepBy記録・GPS生座標・accuracy・フィット経路・Wayスナップショット・変更案をPostgreSQLへ先に保存する。
  • ✅ 審査状態を pending / held / approved / rejected / merge_failed / merged として管理し、状態変更を追記型監査履歴にも残す。
  • ✅ 同じ記録の二重登録・二重承認・二重OSM送信を冪等性キーで防ぐ。
  • ✅ 一般利用者には「記録しました」のみを表示し、OSM送信完了のような誤解を招く表示をしない。

2. ゲストアカウントの扱い

  • ✅ サーバーで記録者の is_guest を必ず確認し、ゲスト記録ではOSM変更案の実行・承認キュー投入を禁止する。
  • ✅ ゲスト記録はStepByのPostgreSQLに保存し、アプリ内の表示・本人限定情報の規則は維持する。
  • ✅ 画面、利用規約、プライバシーポリシー、仕様書に「ゲストの記録はOSMへ公開されない」と明記する。
  • ✅ APIを直接呼んでもゲスト記録を承認・送信できない自動試験を追加する。

3. 管理者向けPC審査画面

  • ✅ 未審査一覧、検索、日時・記録者・新規／既存の絞り込み、審査済み履歴を実装する。
  • ✅ 航空写真とOSMを並べ、GPS生座標、保存経路、対象Way、分割区間、予定タグを表示する。
  • ✅ 承認、却下、保留を簡単に選択でき、却下理由・管理者メモを保存できるようにする。
  • ✅ kumakero.otama@gmail.com で管理画面へログインできることを確認する。
  • ✅ 328件すべてを表示し、旧記録日時・自動分類・件数・経路なし警告を表示する。
  • ✅ 却下時の監査履歴保存エラーを修正し、却下状態と理由を確実に保存する。
  • ✅ 旧記録の承認時に現在OSMへ再フィッティングし、対象Way・分割区間・予定タグを確定する。
  • ✅ 承認時に最新OSMデータとVersion、既存タグ、重複、opt-out、競合を再確認し、安全条件を満たす場合だけStepBy専用OSMアカウントで送信する。
  • ✅ 送信要求、承認者、変更前後、changeset ID、Way/Node/Relation IDとVersion、成功・失敗を追記型監査履歴へ保存する。
  • ✅ 失敗時は履歴を残して再試行可能にし、原因を管理画面へ表示する。競合時は自動上書きしない。

4. 管理者への通知

  • ✅ Google認証ユーザーの公開対象記録が審査待ちになった後に通知イベントを作る。
  • ✅ メールには秘密情報やアクセストークンを含めず、記録ID・日時・審査画面へのリンクだけを記載する。
  • ✅ メール送信失敗で記録保存を失敗させず、通知だけを再試行して履歴を残す。
  • ✅ ゲスト記録とOSM非公開タグだけの記録ではOSM審査通知を送らない。
  • ✅ StepBy専用Gmailから kumakero.otama@gmail.com へ実メールが届くことを確認する。

5. 既存データ移行

  • ✅ 旧データ328件を読み取り専用で抽出し、元記録を一方向ハッシュで識別して審査候補へ取り込む。
  • ✅ ゲスト、経路なし、極端に短い経路を自動分類する。結果は確認待ち218件、保留106件、ゲスト非公開4件。
  • ✅ 旧データにaccuracyがないことと元の保存経路を画面へ表示する。
  • ✅ 新規記録と同じ審査画面から、航空写真とOSMを並べて1件ずつ「公開する／公開しない」を選択できる。
  • ✅ 取り込みではOSM送信を発生させず、元DBへも書き込まない。
  • ⬜ 確認待ち218件を管理者が1件ずつ判定する。
  • ⬜ 保留106件のうち、短すぎる55件と経路要調査51件を確認して公開可否を決める。
  • ✅ 承認した旧記録を現在OSMへ再フィッティングし、既存点字ブロックとの重複を除外する。
  • ⬜ 最初は少量ずつOSMへ送り、changeset・Way・結果・取消し可否を監査履歴で確認する。
