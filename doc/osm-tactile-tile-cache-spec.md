# OSM点字ブロック区画キャッシュ仕様

- 文書状態: 承認済み・実装中
- 初版: 2026-10-24
- 現行仕様版: 1.4（2026-10-25）
- 対象: StepBy正式UI0、`barrierfree-map`バックエンド
- 関連API: 現行`GET /api/osm-tactile-ways`、新規区画API（本書で定義）

## 1. 目的

公開Overpass APIの混雑やタイムアウトに地図表示が直接左右されないよう、OSM上の点字ブロック情報を固定区画ごとに取得・保存する。利用者が現在表示している地図範囲を優先し、取得済み情報を即座に表示しながら、未取得・期限切れの区画だけをバックグラウンドで更新する。

新規問い合わせは、使用許可を得た`armd-01.sakura.ne.jp`を最初に利用し、失敗した場合だけ公開Overpassミラーへ順次切り替える。

次を同時に満たすことを目的とする。

- キャッシュ済み地域を通信待ちなしで表示する
- 地図中心から順に小範囲を取得し、全範囲の完了を待たず描画する
- Overpassへの重複・並列・巨大検索を抑える
- 点字ブロック以外のOSMデータを端末や共有キャッシュへ保存しない
- 現行の色分け、詳細表示、所有者だけの取消し操作を維持する
- 空の検索結果も記録し、同じ空区画を繰り返し検索しない

## 2. 非目的

本仕様では次を行わない。

- OSM道路網、建物、土地利用、背景地図画像、航空写真のオフライン保存
- フィッティング用道路網キャッシュの変更
- OSMへの変更送信・changeset作成・取消し方式の変更
- ブラウザやPWAを完全に終了した状態での常時バックグラウンド収集の保証
- IndexedDBに一言メモ、秘密情報、アクセストークンなどを保存すること

## 3. 検索基準と区画

検索基準はGPS現在地ではなく、Leafletで現在表示している地図の範囲とする。現在地は「現在地中央」が有効な場合に地図中心を移動させるだけであり、取得対象は常に表示範囲から決める。

区画IDにはWeb Mercator標準タイルの`z/x/y`を使い、初期実装は固定ズーム`z=15`とする。日本付近では概ね約1km四方である。実測結果により粒度を変える場合は、キャッシュ世代を更新し、本書の変更履歴へ記録する。

- 地図中心を含む区画を最優先とする
- 次に画面内の区画を中心との距離順に処理する
- 画面内の処理後、外周1列を先読み候補にする
- 低ズームで区画数が多い場合は1回の上限を設け、中央付近を優先する
- Wayが区画境界を越えることを許容し、`osm_type + osm_id`で重複排除する
- 仕様版1.4から、初期表示の仮位置（既定値を含む）では新規取得を開始しない。GPSによる位置確定、利用者による地図移動、または復元済みの有効な表示位置のいずれかで表示範囲が確定した後に取得する
- 低ズームでは広範囲から大量のz15区画が生じるため、初期値として地図ズーム14未満では新規ネットワーク取得を行わず、保存済みキャッシュだけを表示する

## 4. 端末側IndexedDB

データベース名とバージョンはフロント実装で定数化する。少なくとも次のオブジェクトストアを持つ。

### 4.1 `tiles`

| 項目 | 内容 |
| --- | --- |
| `tileId` | 主キー。例: `15/28568/12947` |
| `fetchedAt` | 上流取得に成功した日時 |
| `lastAccessedAt` | 最後に表示対象となった日時 |
| `status` | `ready`、`empty` |
| `osmBaseAt` | 取得元が返すOSM基準日時。取得できない場合は`null` |
| `featureCount` | 当該区画の地物数 |

0件の場合も`status=empty`として保存する。仕様版1.1から、通信・上流・解析エラーは端末キャッシュへ永続化せず、レスポンス上の失敗としてだけ扱う。サーバーの`success`は端末保存時に`ready`へ正規化し、`empty`はそのまま保存する。

### 4.2 `features`

| 項目 | 内容 |
| --- | --- |
| `featureId` | 主キー。例: `way:123`、`node:456` |
| `osmType`、`osmId` | OSM地物の識別子 |
| `geometry` | 表示に必要な点または線の座標 |
| `tags` | `tactile_paving`等、表示ルールに必要な最小限のタグ |
| `changesetId` | StepBy由来判定に必要な場合のみ |

### 4.3 `tileFeatures`

複合キー`tileId + featureId`で区画と地物を対応付ける。同じWayの座標本体を複数区画へ重複保存しない。

### 4.4 保存期限と容量

- 取得後24時間以内: fresh。通信せず表示する
- 24時間超: stale。即時表示しつつバックグラウンド更新する
- `empty`も24時間は再検索しない
- 最終利用から90日超: 削除候補
- 90日超データのcleanup判定は6時間周期で実行する
- 初期容量上限: 25MB
- 上限超過時: `lastAccessedAt`の古い区画からLRU削除する
- IndexedDBが使えない場合: メモリキャッシュで継続し、画面を停止させない

地物の参照が全区画から外れたときだけ`features`から削除する。

## 5. 取得スケジューラ

1. OSM情報表示がONになったら、その時点の`map.getCenter()`、`map.getBounds()`、`map.getZoom()`を初回anchorとして一度だけ固定し、anchorから必要区画を算出する。位置が未確定の場合は取得を開始せず、最初に有効な表示位置が確定した時点で一度だけcaptureする
2. IndexedDBの該当区画を読み、fresh・staleを直ちに描画する
3. 地図操作中は新規取得を開始しない
4. 初回anchorのactive取得または`pending`再確認が残っている間は、`moveend`、`zoomend`および現在地追従による地図移動を取得対象へ反映せず、初回処理を中断・再起動しない
5. 初回anchorがsettleした後に発生した`moveend`または`zoomend`から500ms後に限り、現在の表示範囲で次の取得キューを構築する
6. 中央区画、画面内、外周1列の順に取得する
7. 1区画の完了ごとに保存・重複排除・再描画する
8. 位置確定前、および地図ズーム14未満では新しい取得キューを作らない
9. 算出したtile集合を正規化した署名で管理し、同じ集合の取得が実行中または完了済みである間は、`moveend`等が再発火しても同じ処理を再開しない
10. OSM情報表示をOFFにした時点で初回anchor、tile集合署名、client側のactive要求と`pending`再確認タイマーをresetする。再度ONにした場合は、その時点の有効な表示範囲を新しい初回anchorとしてcaptureする

ここでsettleとは、初回anchorに属する全対象tileが`ready`、`empty`または確定した`error`となり、client側にactive要求および`pending`再確認待ちが残っていない状態をいう。端末からの区画取得は原則1件ずつとする。画面内の取得が完了する前に外周先読みを開始しない。通信節約設定が利用可能で有効な場合は、外周先読みを行わない。通信種別を取得できない環境でも基本機能は動作させる。初回settle後に表示範囲が変わった場合は旧世代の未開始キューと再確認タイマーを破棄するが、同一tile集合への再移動では進行中の処理を中断・再生成しない。

## 6. バックエンドAPI

新規APIの予定形は次とする。

```http
GET /api/osm-tactile-tiles?tiles=15/x/y,15/x/y,...
Authorization: Bearer <StepBy access token>
```

- `z=15`以外、無効な`x/y`、上限超過件数は拒否する
- 1リクエストの区画数には小さな上限を設ける
- サーバーが`z/x/y`からbboxを算出し、クライアント指定の任意巨大bboxを受け付けない
- 区画ごとに`success`、`empty`、`pending`、`error`を返す。`pending`と`error`はレスポンス上だけの状態であり、freshな永続キャッシュにはしない
- 一部区画が失敗しても成功分を返す部分成功を許容する
- 全区画が失敗した場合は、仕様版1.1の統一契約として`success: false`、`partial: false`、`allFailed: true`を返す
- 仕様版1.4から、キャッシュがない区画は更新を開始して最大2秒だけ結果を待つ。2秒以内に完了しなければ`pending`と`retryAfterMs`を返し、HTTP接続を待たせず、同じ更新処理をサーバーのバックグラウンドで継続する
- 1回の表示範囲更新で新規に投入するcold区画は中央優先で最大4件とする。サーバー全体の背景更新待ちも最大8件とし、上限を超える区画は新しいOverpass処理を作らず`pending`を返す
- z15の小範囲検索はOverpass QLの実行上限を4秒、各ホストのHTTP上限を約4.5秒とし、2ホストを試す総待機を約9秒以内に抑える
- 全区画が`pending`の場合は`success: false`、`partial: false`、`allFailed: false`、`pending: true`とし、確定失敗と区別する
- 現行`/api/osm-tactile-ways`は移行・ロールバック用に当面残す

Overpassクエリは`tactile_paving`表示ルール、固定bbox、`out meta geom qt`に限定する。OSM書込みAPIは呼ばない。

## 7. サーバー共有キャッシュ

PostgreSQLへ公開OSM情報だけを保存する区画キャッシュを追加する。想定スキーマは`osmcache.tactile_tiles`であり、少なくとも次を持つ。

- `tile_id` 主キー
- `fetched_at`、`last_accessed_at`、`osm_base_at`
- `status`（`success`、`empty`）
- `features JSONB`
- `feature_count`
- `updated_at`

仕様版1.1から、永続化する`status`は取得成功を表す`success`と、正常に0件だった`empty`だけとする。`error`はAPIレスポンス上でのみ表し、freshな成功結果としてPostgreSQLへ保存しない。初期実装では`error_count`、`next_retry_at`列を設けず、上流ホストごとのメモリ内cooldownで再試行間隔を制御する。

共有キャッシュの方針は次とする。

- 24時間以内: 即時返却し、Overpassへ問い合わせない
- 24時間～30日: 即時返却し、裏で更新する
- 30日超: staleとして表示可能だが、更新優先度を上げる
- 最終利用から90日超: 定期削除候補。cleanup判定は6時間周期で実行する
- 同一タイルの同時更新要求は1本へ統合する
- 同一タイルの更新中Promiseをin-flightとして共有し、HTTPが`pending`を返した後も新しいOverpass要求を重ねず、バックグラウンド処理を完了させる
- サーバー全体のOverpass同時実行数は1を初期値とする
- タイル更新の失敗はメモリ内failure cooldownで抑制する。cooldown中は新しいOverpass要求を開始せず、`error`と`retryAfterMs`を即時返す。失敗状態はfreshとして永続化しない
- DB障害時はメモリキャッシュへフォールバックする
- 観測ログは`tileId`、取得元（memory／db／fresh／stale／pending／error）、HTTP応答時間、Overpass待機時間、キュー深度だけを記録し、生の緯度経度、利用者ID、トークン等を含めない

複数利用者が同じ区画を要求しても、Overpassへの検索はキャッシュ更新1回だけにする。

## 8. 所有権・色分け・プライバシー

サーバー共有キャッシュにはStepBy記録との照合結果、利用者固有の取消し可否、一言メモを保存しない。キャッシュした公開OSM地物を返す際、changeset ID等をまとめて既存PostgreSQLのStepBy記録と照合し、公開情報としてStepBy記録かどうか・記録ID・記録者を付与する。さらにリクエスト利用者本人に限り、取消し対象IDと取消し可否を付与する。

端末のIndexedDBには、緑線と公開詳細を再表示するための公開情報（StepBy記録かどうか・記録ID・記録者）を保存してよい。ただし、本人専用の取消し対象IDと取消し可否は永続化せず、利用者IDで分離した30分以内のメモリキャッシュだけで合成する。利用者が切り替わった場合、前利用者の取消し権限表示を再利用しない。

- StepBy由来か
- StepBy内部の記録ID
- 記録所有者
- 現在の利用者が取消し可能か

本人限定タグや一言メモを、公開OSMキャッシュまたは他人向けレスポンスへ混入させない。OSMトークン、Cookie、秘密鍵をキャッシュへ保存しない。

## 9. OSM公開・取消し後の無効化

StepByからOSM公開または取消しが成功した場合、変更前後のgeometryと交差する端末・サーバー区画を無効化する。

- サーバー: 該当区画をメモリキャッシュとPostgreSQL共有キャッシュから削除し、次回表示時に再取得する
- フロント: 成功レスポンスの`invalidatedTactileTileIds`で通知された区画IDをIndexedDB上でstaleにする
- 画面: StepByのPostgreSQL記録を優先して即時反映し、Overpassへの反映遅延を待たない

対象区画は変更前と変更後の両座標から算出し、公開と取消しの双方で古い表示を残さない。OSM送信が失敗・競合停止した場合は無効化せず、公開キャッシュを成功扱いで更新しない。

## 10. 旧方式からの移行

現在の`localStorage`キー`osmTactileDisplayCache.v1`は対象区画が明確でないため、fresh区画へ直接変換しない。

1. 新方式の初回表示では旧キャッシュを一時表示してよい
2. 表示範囲の新規タイル取得をバックグラウンドで行う
3. 表示範囲の新規タイルが揃った後に旧キャッシュを削除する
4. 新APIが利用不能な場合は機能フラグで現行半径APIへ戻す

旧APIへフォールバックするのは、新APIが未実装であることを示すHTTP 404／501の場合だけとする。タイムアウト、接続失敗、HTTP 5xx、不正JSON、全区画失敗、区画単位の`pending`／`error`は一時障害または背景更新中として既存表示を維持し、旧1km・10km検索を重ねない。`retryAfterMs`以降も同じ表示範囲が有効な場合だけ新APIへ再確認する。

新API公開、UI切替、旧API整理を別段階にし、一括切替しない。

## 11. 失敗時の動作

- Overpass障害: 保存済みfresh/staleを表示し続ける
- 未取得区画の障害: その区画だけレスポンス上の`error`とし、永続fresh保存せず、地図全体をエラーにしない
- IndexedDB障害: メモリキャッシュとネットワーク表示で継続する
- PostgreSQLキャッシュ障害: メモリキャッシュまたはOverpassへフォールバックする
- 地図移動: 古い範囲の未開始要求を破棄し、新しい中心へ優先順位を移す
- 連続失敗: バックオフを適用し、即時再試行を繰り返さない
- 全区画失敗: `success: false`、`partial: false`、`allFailed: true`で返し、保存済み表示は維持する
- キャッシュなしで2秒以内に取得未完了: `pending`を返してサーバー更新を継続し、画面は待機表示で塞がない
- `pending`: 旧APIを呼ばず、指定された再確認時刻まで同一タイルを要求しない
- 位置未確定またはズーム14未満: 保存済み表示だけを維持し、新規取得しない

画面全面を塞ぐローディング表示は再導入しない。

## 12. テスト

OSM書込みを一切行わず、Overpass通信は原則モックする。

- タイルIDとbbox変換、境界値、不正入力
- 表示範囲から必要区画を算出し、中心距離順に並べる
- `moveend`／`zoomend`の500msデバウンス
- 古い取得キューの中止
- 位置確定前の取得禁止と、ズーム14未満での新規取得禁止
- 同一tile集合で`moveend`等が再発火しても取得処理を再開しないこと
- ON時のcenter／bounds／zoomが初回anchorとして固定され、初回active／pending中の地図移動で中断・再起動しないこと
- 初回settle後の`moveend`だけが次範囲を開始し、OFFでanchorをreset、再ONで現在の有効範囲を再captureすること
- fresh、stale、empty、期限切れ判定、および端末側`success`→`ready`正規化
- `error`を端末・サーバーのfresh永続キャッシュへ保存しないこと
- 地物の重複保存・重複描画防止
- 0件区画への重複通信防止
- 同一タイルの同時要求統合
- 最大2秒での`pending`応答後も、サーバー側の同一in-flight更新が継続・再利用されること
- `pending`で旧APIへフォールバックせず、`retryAfterMs`前に再要求しないこと
- タイルfailure cooldown中にOverpass要求を追加しないこと
- Overpass同時実行上限とバックオフ
- 部分成功レスポンス
- IndexedDB／PostgreSQL障害時フォールバック
- LRU・25MB・90日削除
- 90日cleanupの6時間周期制御
- 全区画失敗契約（`success: false`、`partial: false`、`allFailed: true`）
- 上流ホストcooldown（`error_count`、`next_retry_at`列を使わないこと）
- StepBy色分け、所有権、本人削除、メモ非公開の回帰
- OSM公開・取消し後の該当区画無効化
- 現在地と異なる場所へ地図を動かした場合の表示範囲優先
- 現行半径APIへのロールバック

## 13. 完了条件

- キャッシュ済み表示範囲を目安300ms以内で描画する
- 初回も1区画ごとに描画し、全範囲の完了を待たない
- キャッシュがない区画APIの応答時間p95を2秒以内とし、時間内に上流取得が終わらない場合は`pending`で画面へ制御を返す
- 点字ブロック以外のOSM地物をIndexedDB／共有キャッシュへ保存しない
- `empty`を取得済みとして扱う
- 同一タイルへの同時Overpass要求が最大1件である
- `pending`応答後もサーバーの背景更新を継続し、同一タイルの追加Overpass要求を発生させない
- 地図移動時はGPS位置ではなく表示中の範囲を優先する
- 初期位置確定前、ズーム14未満、同一tile集合の再通知では不要な新規取得を開始しない
- 初回anchor処理中の地図移動で取得対象を切り替えず、settle後の移動だけを次範囲として処理する
- OSM情報表示のOFF→ONで古いanchorを再利用せず、再ON時のcenter／bounds／zoomをcaptureする
- サーバー再起動後もPostgreSQL共有キャッシュを再利用できる
- 従来方式よりOverpass要求数を増やさない
- 既存の色分け、詳細、本人削除、プライバシー、記録・フィッティングを壊さない

## 14. ロールバック

- 新APIとUI切替を機能フラグで分離する
- 異常時はUIを現行`/api/osm-tactile-ways`へ戻す
- 新キャッシュテーブルは公開OSMの派生データだけであり、ロールバック時に既存記録を変更しない
- DBマイグレーションは既存テーブルを破壊・改名しない追加方式とする
- IndexedDBのバージョン更新に失敗しても、旧キャッシュまたはメモリ表示へ戻す
