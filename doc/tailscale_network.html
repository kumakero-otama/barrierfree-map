4. セキュリティと認証

TLS

Funnel リレー側で TLS 終端する。自宅サーバまでの中継は Tailscale の WireGuard 暗号化トンネルで運ばれるため、平文区間は tailscaled → 127.0.0.1:3000 のループバックのみ。インターネット上には平文区間が存在しない。

認証 (Cookie / Bearer)

  • サーバは Set-Cookie: session=… と Authorization: Bearer … の両方をサポート （server/auth_user.js、 server/auth_token.js）。
  • フロントは GitHub Pages (kumakero-otama.github.io) 上で動き、API は *.ts.net で受けるため、ブラウザ視点では クロスサイト通信。
  • クロスサイトで Cookie を載せるには SameSite=None; Secure が必須。 Safari/Brave/設定強化 Firefox では third-party cookie が遮断されるケースがあるため、 Bearer 経由のフォールバック動作を本番で必ず確認する。

CORS

server.js の isCorsOriginAllowed は *.github.io を正規表現で許可済み。 したがってバックエンド側のホスト名を loophole から *.ts.net に変えても CORS の追加修正は不要。

確認済み: GitHub Pages のオリジン https://kumakero-otama.github.io は現行 CORS ルールでカバーされる。

5. 変更が必要な箇所

場所変更内容
StepBy/UI0/config.js API_BASE_URL を https://barrierfree-map.loophole.site から https://<machine>.<tailnet>.ts.net に変更
StepBy/UI0/auth/token_client.js 同上 DEFAULT_API_BASE_URL を新URLに変更
barrierfree-map/ecosystem.config.js barrierfree-map-loophole エントリを削除（または無効化）。 Tailscale 側は systemd 管理なので PM2 への追加は不要。
サーバ環境 tailscale up → tailscale funnel --bg 3000 を一度実行。 設定は /var/lib/tailscale/ に永続化される。
(任意) CORS_ALLOWED_ORIGINS 必要なら明示的に GitHub Pages のオリジンを追加。ただし正規表現で既に *.github.io が許可されているため通常は不要。

8. 運用上の留意点

  • マシン名 = 公開ホスト名。tailscale set --hostname=barrierfree-map のように名前を整えると、URLが barrierfree-map.<tailnet>.ts.net になり可読性が向上する。
  • Funnelの有効化はマシン単位。新しいマシンに移すときは tailscale funnel --bg 3000 を改めて実行する必要がある。
  • 同一サーバから複数アプリを公開したい場合はパスベースで分けるか、 別マシンを tailnet に追加する。Funnel は 1ノードあたり 1リスナー。
  • 障害時のフォールバック: localhost:3000 は変わらないので、 Tailscale 障害時は SSH などで叩いて確認可能。フロント側を API_BASE_URL だけで切替できるように維持する。
